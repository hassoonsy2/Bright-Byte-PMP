# Quick Task 261020-12y: Per-project Slack notifications (Ambis only) — Summary

Each project in the `ambis` workspace can now be linked to one Slack channel via a Slack incoming-webhook URL. Work-item events (created, state changed, assignee changed, priority changed, comment added, deleted) post one readable Block Kit message per action, each event individually toggleable. Every other workspace gets 404 from the endpoints and sees no UI.

## What was built

**Task 1 — backend config (`0d8b9257e9`)**

- `SLACK_NOTIFICATION_WORKSPACES` setting (comma-separated slugs, empty = feature off everywhere) + `_parse_slug_allowlist` helper in `plane/settings/common.py`.
- `ProjectSlackNotification` model in `plane/db/models/integration/slack.py` (legacy `SlackProjectSync` untouched): Fernet-encrypted `webhook_url`, `is_active`, six `notify_*` toggles, `last_delivered_at`, `last_error`; conditional unique constraint per project. Hand-written migration `0124_projectslacknotification`.
- `plane/utils/slack_notification.py` (no model imports): strict `https://hooks.slack.com/services/` URL validation (scheme, exact host, no port/userinfo/query/fragment), masking (last 4 chars), allowlist check, mrkdwn escaping, `post_to_slack` (10 s timeout, no redirects, errors never include the URL).
- `GET/PATCH/DELETE /api/workspaces/<slug>/projects/<id>/slack-notification/` and `POST …/slack-notification/test/` — project ADMIN only; allowlist check runs before the permission check (404 for other workspaces). GET never returns the full URL. DELETE hard-deletes so the secret isn't retained.
- `render.yaml`: `SLACK_NOTIFICATION_WORKSPACES=ambis` on `bright-byte-api` and `bright-byte-worker`; `APP_BASE_URL=https://pmp.bright-byte.co` on the worker (it had neither APP_BASE_URL nor WEB_URL; on Render WEB_URL is the API host, so links use APP_BASE_URL).

**Task 2 — delivery (`35438a83b8`)**

- Message formatting helpers (`describe_activity`, `build_change_lines`, `build_issue_url`, `build_slack_payload`) — links to `{APP_BASE_URL}/{slug}/browse/{IDENT}-{seq}/`.
- `plane/bgtasks/slack_notification_task.py::send_slack_notification` — re-checks allowlist + active config, skips drafts, resolves deleted items via `Issue.all_objects`, honours toggles, one message per action, max 2 retries on 429/5xx/network, records `last_delivered_at` / `last_error`. Registered in `CELERY_IMPORTS`.
- Hook in `issue_activity` right after `bulk_create`, in its own try/except; zero queries when the allowlist is empty.
- Tests: `plane/tests/unit/utils/test_slack_notification.py` (48) + `plane/tests/unit/bg_tasks/test_slack_notification_task.py` (12, DB mocked) — 60 passed.

**Task 3 — web card (`b4c7f13ce2`)**

- `ProjectSlackNotificationService` + types, `useProjectSlackNotification` SWR hook, `SlackNotificationAutomation` card rendered on Project Settings → Automations after Auto-close. Renders nothing while loading, on error, or on 404. Webhook URL input (masked hint when saved), Active toggle, six event toggles, Save / Send test message / Disconnect, last-delivered / last-error status. Strings via `t(key, { defaultValue })`; no locale JSON changes.

## Deploy / setup (required before it works in production)

1. Render's api service has NO pre-deploy command, so apply migration 0124 manually: `render jobs create <api-srv> --start-command "python manage.py migrate"`.
2. If the render.yaml blueprint isn't synced to the dashboard, set `SLACK_NOTIFICATION_WORKSPACES=ambis` on bright-byte-api and bright-byte-worker, and `APP_BASE_URL=https://pmp.bright-byte.co` on bright-byte-worker, then redeploy api, worker and web.
3. Slack side: someone with Ambis Slack admin rights creates a Slack app (api.slack.com/apps) with Incoming Webhooks enabled, adds one webhook per target channel, and pastes each `https://hooks.slack.com/services/…` URL into the matching project's Settings → Automations → Slack notifications card, then clicks "Send test message".

## Post-deploy UAT

1. In `ambis`, Project Settings → Automations shows the Slack card; in another workspace it's absent and the GET endpoint returns 404.
2. Save a webhook; GET shows only the masked URL; "Send test message" lands in the channel.
3. Create a work item, change state/assignee/priority, comment, delete — one message each with a working `pmp.bright-byte.co/ambis/browse/IDENT-N/` link; turning a toggle off suppresses that event.
