<objective>
Replace the plain `!==` string comparison in the live server's requireSecretKey middleware with `crypto.timingSafeEqual` to eliminate the timing-oracle vulnerability that allows an attacker to infer secret characters by measuring response latency.

Purpose: The existing comparison at auth-middleware.ts:38 is a timing oracle. An attacker who can measure HTTP response times can brute-force the secret character-by-character. Node's built-in crypto.timingSafeEqual (available since Node 6, project runs Node 22) closes this.
Output: Updated auth-middleware.ts with constant-time compare and a length-safety pre-check; Vitest test file covering all four auth branches.
</objective>
