<objective>
Harden the three insecure-by-default Django settings (ephemeral SECRET_KEY, wildcard ALLOWED_HOSTS, CORS allow-all with credentials) and add a boot-time guard that rejects insecure configuration before the process serves any traffic.

Purpose: These three defaults exist in common.py and are exploitable whenever environment variables are absent or misconfigured. The guard ensures the process never silently starts in a vulnerable state in production.
Output: Updated common.py with guard block, updated render.yaml with ALLOWED_HOSTS, new unit test file covering all four guard conditions.
</objective>

    The guard block must:
    1. Import ImproperlyConfigured at the top of the guard block (not at file top, to avoid disrupting the existing import order): `from django.core.exceptions import ImproperlyConfigured`
    2. Build a `_boot_errors` list, appending an error string for each of three conditions:
       - Condition A: `not os.environ.get("SECRET_KEY")` — error text: "SECRET_KEY env var is required in production. Without it, a random key is generated per process restart, invalidating all sessions and CSRF tokens."
       - Condition B: `not DEBUG and "*" in ALLOWED_HOSTS` — error text: "ALLOWED_HOSTS='*' is not permitted in production. Set ALLOWED_HOSTS to comma-separated exact hostnames (e.g. bright-byte-api.onrender.com)."

    3. Raise `ImproperlyConfigured` only when `_boot_errors and not DEBUG`. The error message is a newline-joined list prefixed with "Insecure configuration — fix before running in production:".
    4. Guard is entirely silent (no raise, no print, no log) when `DEBUG` is `True`.

    Rationale for `globals().get("CORS_ALLOW_ALL_ORIGINS")`: `CORS_ALLOW_ALL_ORIGINS` is only defined in the `else` branch at line 171; using `globals().get` avoids a NameError when the variable was never defined (i.e., when origins are set correctly).

Do NOT add ALLOWED_HOSTS to the worker, beat-worker, or migrator service blocks — those services do not receive HTTP traffic and do not use ALLOWED_HOSTS for routing decisions. | Cross-origin browser request → Django API | CORS policy determines whether foreign origins can send credentialed requests                                                        |
